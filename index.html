scan-e2e-tests test pages

Static test pages for the Usercentrics V3+ Scanner regression suite. Each variant is a self-contained page designed to exercise a specific aspect of scanner behaviour. The suite that scans these pages and asserts on the results is scan-e2e-tests on Bitbucket (planned canonical location alongside other SE repos).

Variants

PathScopeNotes
default/ 10 commonly-deployed services across Essential / Functional / Marketing Baseline regression target (current).
missing-one/ Same 10 services with LinkedIn Insight Tag intentionally absent Threshold-tolerance target: the consuming scenario expects all 10 with a 90% threshold, so 9/10 passes and the missing service is surfaced in the detection report.
query-param/ Minimal target that reflects location.search Regression target for the scan-api httpRequestInjections feature (SE-3076). The suite injects query parameters and asserts they reach the scanned URL.
late-tracker/ Pinterest Tag (s.pinimg.com) injected ~5s after load Regression target verifying the scanner's delayed-activity observation window still records a late-firing tracker.
redirects/ Client-side redirect to redirects-target/ (Bing UET, bat.bing.com) Regression target verifying the scanner follows a same-domain redirect and scans the destination. Client-side redirect only — GitHub Pages cannot emit a real HTTP 301/302.

Conventions

  • One subdirectory per scenario. Each subdirectory ships its own self-contained index.html.
  • Pages are served from main on GitHub Pages — no build step.
  • All variants load the Usercentrics V3 sandbox CMP with settingsId tPIg6i7JCCD-va unless a scenario specifically tests a different setup.
  • Services are loaded as plain <script src> / <iframe> / <link> tags. Autoblock-style type="text/plain" data-usercentrics is reserved for scenarios that explicitly test that behaviour.
